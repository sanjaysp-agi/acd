PRAC-requested monitoring topics — from AR Section 4 to the Section 16.3 paragraph

Section 16.3 also carries a second kind of content: risks the PRAC has explicitly asked to be presented, taken from the PRAC Assessment Report (AR) that follows each PBRER submission. The template offers three optional paragraphs for this — which one applies depends on exactly what the AR's request says.

AI instructions — extracting the PRAC request and selecting the right paragraph
  1. Open the PRAC Assessment Report and locate the section titled "Issues to be addressed in the next PSUR" (numbered "4." at the front of the AR, before the main "PSUR Data" body). This is the forward-looking request list for the next PBRER cycle — do not confuse it with the "Requests from previous PSUSA" subsection found later in the AR body, which only recaps an earlier cycle's request and its resolution.
  2. For every request bullet found, extract: the risk/topic name exactly as named; the MAH(s) it is addressed to; the requested safety-concern classification (identified vs. potential risk) and whether it is new or a reminder of an existing one; the PBRER section(s) named for presentation (16.3 and/or 16.4); any explicit mention of "cumulative review"; and any explicit statement that the risk should be monitored by "routine pharmacovigilance activities" and not presented in future PSURs.
  3. From the AR's cover page, extract the placeholder values every template needs: the procedure number (Procedure no.: EMEA/H/C/PSUSA/…/……) and the reporting interval (Period covered by the PSUR: DD/MM/YYYY to DD/MM/YYYY).
  4. Apply the decision rule, in this order:
    • Routine monitoring, not required in future PSURs → Paragraph 1.
    • Present new evidence / characterisation in Section 16.3 (and/or 16.4) → Paragraph 2. Keep the "particular focus on new evidence from the literature" clause only if the request's own rationale cites literature or treatment guidelines as the trigger; otherwise adapt the clause to whatever evidence type is actually named.
    • Cumulative review explicitly requested (with no standing 16.3 presentation obligation yet) → Paragraph 3.
    • None of the above (e.g. a formulation-reporting instruction, a PSUR-frequency change, a labelling-only update) → flag as out of scope for this selector and route to manual PV / regulatory handling.
  5. Populate the selected template's placeholders with the values from steps 2–3, and attach the mandatory Section 16.3 data table and Evaluation narrative beneath it, using the sourcing and writing logic already established above.
  6. Flag for human sign-off: confirm the AR's own adoption / "dated" reference against its official cover page or EPITT record — an AR does not always state that field as explicitly as it cites the previous cycle's, so it should be verified manually rather than assumed from document metadata.

Literature analysis for Section 16.3

Alongside the post-marketing case review, Section 16.3 includes a dedicated literature analysis for the topic, run against BILIT — Boehringer Ingelheim's internal literature database (which itself indexes Medline and Embase). A hit is written up either as a general literature finding (an abstract plus Boehringer Ingelheim's own assessment) or, when the underlying publication describes a single or small number of patients, as a case report with its own title and citation. Because publication is selective — an article appears because it was judged notable, not because it is representative of overall frequency — the literature analysis is used qualitatively: for external corroboration or mechanistic insight, rather than as a count.
